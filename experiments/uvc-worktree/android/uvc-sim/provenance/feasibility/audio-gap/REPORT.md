# 视频替代后的音频缺口与合成场景

基线 `c1afb3f61fa309bde0437fa2019c352ddc1792ba`。本轮仅复用既有固定证据，未联网、构建、加载 native 或操作设备。附件 [scenario-contract.json](scenario-contract.json) 是**尚未实现或执行的场景设计**，不是测试通过记录；其描述键不是新增 PRD 测试编号。

**替换 libyuv 只能处理视频转换问题。它不提供 UAC 驱动、音频设备枚举、实际音频路由、麦克风送回电脑或 A/B/C/D 四路闭环。** UVCAndroid 的视频路线与 AndroidUSBCamera 的旧 UAC 二进制是两个候选来源，不能混用其源码、许可和产物结论。视频能到达 Android 也不证明任何一路桌面音频已成立。[既有总报告](../../followup/GATE_REPORT.md)、[视频替代证据](../../followup/video-alternatives/README.md)

## 四路分别需要什么

A/B/C/D 定义来自主集成对话已通过 Library 核对的冻结 PRD v1.5、版本 0、5.1–5.4；Library ID 记录在 JSON。本地未重建 PRD 副本。下表是工程成本范围，不是新增预算、报价或工期承诺。

| 路径 | 必须保留/补足的能力 | 成本边界与不能代证的事项 |
|---|---|---|
| **A：远端 → 用户耳朵** | 用户原有远端收听，明确扬声器/耳机和实际输出。 | 可能需保留电脑直出或接口直接监听。采集/提取不能破坏收听；C 有 PCM 不证明 A 可听。手机监听中转不设为默认，不能把其延迟/回声与新增输出链路隐含算入视频替换。 |
| **B：本地麦克风 → 电脑会议** | 原会议输入和 mute 行为保持可用。 | 麦克风接到 Android 不代表声音会回电脑。若硬件需要分路/混音/接口，应单独核实拓扑、增益、供电及电脑输入选择；不通过安装电脑代理或新增手机中转隐含补齐。 |
| **C：远端 → Android 记录** | 可确认的远端提取/输入、格式、权限、真实路由、停止与健康证据。 | HDMI 视频转换不会产生音频输入。需系统 USB 音频或独立 UAC 路线及相应接线；USB 被枚举、read>0、文件增长都不独证有效远端内容。 |
| **D：本地麦克风 → Android 记录** | 在 B 仍成立的条件下，取得可确认的本地声音分支及其 mute/同意边界。 | 新增成本取决于已有接口能否分出 D；不得假定 C 包含本地声，也不得静默换手机麦。是否需要外置接口/混音/提取由选定拓扑决定，不预定采购或价格。 |

因此成本至少分为：实际接线/硬件能力，Android 输入与生命周期，四路验证及证据。只通 C 可标远端记录，不能标双向纪要。会议 mute、物理 mute、Sidecar stop 分别验证，不能互相代证；物理 mute 位于分路前后，也可能改变 D 的实际覆盖。G0 模拟可以继续，G2 四路实听回放仍需单独完成。

## 三条候选路线仍缺什么

| 路线 | 已有固定证据 | 音频与许可未决项 | 纯合成能验证的范围 |
|---|---|---|---|
| **UVCAndroid + 官方 libyuv 视频替代** | UVCAndroid `fcdae5f9a194e2111d57019176b53470a120415b`；官方 libyuv `3e38ce50589d9319badc0501f96d6c5b2b177472` 的最小转换候选。 | 音频仍须独立选路线。官方 libyuv 的 BSD/专利文本不清除 libusb LGPL、libuvc、JPEG、Android/Java 传递依赖和最终产物义务。替换还未证明所有旧定制源已从最终构建排除；本轮不把原 libUACAudio 塞入该路线。 | 视频失败只影响实际关联流；音频 lease、同意、停止和恢复不被视频重连自动触发。不能测音频枚举、真实路由或可听覆盖。 |
| **Android 系统 USB 输入 + AudioRecord** | AOSP `android-15.0.0_r1` → `4e43ad12e1b211f15152e9c5b16b0fe88e6b93f3`：首选设备不保证实际路由，拔除后系统可能重选。 | 可避免 App 分发旧 UAC blob，但不保证 OEM 把接口识别成输入，也不清除独立视频 native 义务。需 RECORD_AUDIO、适用前台限制、设备/路由/配置通知和政策静音处理。公开 API 不保证路由与每个 PCM 帧的原子归属。 | 偏好成功但路由错误/未知时不提升健康；拒收旧 lease；权限撤销、中断、主动恢复、独立流影响范围。模拟不能证明切换窗口从未收进手机麦。 |
| **nExtCamera/libuac 新 native 路线** | `17a6ba0a09309a6890ec338826de43a256f89813` 有 Jakub Księżniak 的 Apache 2.0 源码头；其 Android recipe 依赖 libusb。 | 是新实现候选，不给原四 ABI UAC 补授权。需独立锁定 libusb/工具链/runtime、JNI/FD/权限接入、每 ABI 构建及最终包、通知和适用 LGPL 材料。不能把 camplayer 根 GPLv3 的 JNI 当作 Apache 子树的一部分直接采用。 | 驱动接口可用 fake 表达打开/停止/迟到回调/排空/一次释放；不能验证 iso 传输、设备兼容、真实停止时间或许可闭环。 |

来源：[UAC 固定源码与系统音频研究](../../followup/uac/REPORT.md)、[视频来源和许可边界](../../followup/video-alternatives/README.md)、[Camera2 平台边界](../../followup/platform-alternatives/REPORT.md)。这些都是静态证据；libyuv 或 Camera2 的视频替代不会自动完成音频工作。

## 合成方案如何使用

JSON 以合成设备、lease、控制/数据/存储 actor 和确定的事件顺序表达下列检查，不打开 AudioRecord 或 USB：

- 偏好成功但实际路由错误、路由/config 缺失或过期；read>0/文件增长/静音标志不足以证明健康。
- 路由通知迟到、读期间往返切换；用**测试专用来源真值**展示同样公开观察可对应不同实际音源。该真值不能交给实际适配器作为不存在的 API，再声称问题解决。
- 单输入与共享输入断开，按实际关联范围停止；独立的视频或 D 不因 C 故障自动停止，共享物理附件则按绑定同时中断相关流。
- 权限撤销、迟到打开完成、旧帧/旧失败回调；旧代不能复活或干扰新代，释放尝试不得重复。
- 重连、重新授权、解除策略静音不自动恢复；需主动确认、旧操作排空和新的有效证据。
- 采样率/通道/时基变化不重解释旧 PCM；只有 C 时不生成双向纪要；三种 mute/stop 独立注入。
- 写盘和驱动关闭阻塞时，准入失效不等 I/O；超时不报告已完成关闭，既有尾部封存/缺口与隐私规则保持适用。

合成方案能检验控制顺序、所有权、拒收和不夸大证据的实现规则。它不能证明真实四路可听、回声/增益、手机与接口时钟、OEM 路由原子性、供电或设备支持。尤其“来源未知”是证据缺失，不能补成健康或新增一个自动切麦分支。所有产品投影继续采用已有 PRD 状态。

本轮仅检查 JSON 可解析、描述键唯一、断言均引用已声明谓词及静态禁用约束；没有执行这些场景，也没有完成任何 G0/G1/G2 退出。下一步若实施，应先选一条视频路线与一条音频路线、明确实际接线，再在独立 fake harness 中落实契约；真实输入和 native 接入仍受既有门禁约束。
