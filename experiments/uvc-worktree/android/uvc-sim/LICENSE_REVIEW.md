## Publication differences and permission surface

The fixed `libuvccamera/build.gradle` declares AndroidX core 1.13.1, legacy-support-v4 1.0.0, appcompat 1.6.1 and annotation 1.8.0. Both published POM and Gradle runtime variant additionally declare `cn.hutool:hutool-core:5.8.35`. Its [parent POM](https://repo.maven.apache.org/maven2/cn/hutool/hutool-parent/5.8.35/hutool-parent-5.8.35.pom) declares MulanPSL-2.0; do not label it Apache-2.0 from the wrapper's POM. Parent JUnit/Lombok test declarations do not by themselves become runtime dependencies.

Read-only inspection of `classes.jar` found the bytes `cn/hutool` in `com/serenegiant/utils/FileUtils.class`. The [fixed source FileUtils.java](https://github.com/shiyinghan/UVCAndroid/blob/fcdae5f9a194e2111d57019176b53470a120415b/libuvccamera/src/main/java/com/serenegiant/utils/FileUtils.java) has no corresponding hutool import, and the inspected publication script contains no explicit hutool dependency insertion. **The difference is present in the published class file, not only POM metadata.** This observation does not establish when or why the publication changed. Excluding hutool from dependency resolution is not a verified repair: reachable references could still fail at runtime.

Both the inspected AAR manifest and [fixed source manifest](https://github.com/shiyinghan/UVCAndroid/blob/fcdae5f9a194e2111d57019176b53470a120415b/libuvccamera/src/main/AndroidManifest.xml) declare CAMERA, RECORD_AUDIO, MANAGE_EXTERNAL_STORAGE, READ_EXTERNAL_STORAGE, WRITE_EXTERNAL_STORAGE and FOREGROUND_SERVICE. They also declare USB host and required OpenGL ES 2.0. These declarations are not permission grants and do not prove that every path needs them. They do mean an unreviewed AAR merge could broaden the application's requested capabilities.

For the next source build, isolate the selected video API and disable unused sample/photo/video-to-gallery, audio and external-file helper paths. Review the merged manifest and actual call graph; remove unused external-storage/all-files declarations and avoid adding audio permissions for this video adapter. Keep app-owned permissions only where the separately authorized app feature needs them. Determine CAMERA and foreground-service requirements from the chosen Android USB/API path and target SDK; do not assume either that all UVC access needs CAMERA or that CAMERA can always be removed. The final package must not introduce unmanaged preview snapshots, media-store writes, content logs or automatic recording through sample helpers.

## Java/Kotlin graph and static ELF evidence

AndroidUSBCamera's fixed libausbc build declares appcompat 1.3.1, constraintlayout 2.0.4, material 1.3.0, xlog 1.11.0 and project modules libuvc/libnative. libnative additionally declares core-ktx 1.3.2, appcompat 1.2.0 and material 1.3.0; the root Kotlin Gradle plugin is 1.5.20. These overlapping declarations require actual resolution, including Gradle variants and transitive version conflicts. Demo-only SDKs must not be imported by copying the sample project.

[XLog 1.11.0 POM](https://repo.maven.apache.org/maven2/com/elvishew/xlog/1.11.0/xlog-1.11.0.pom) and [appcompat 1.3.1 POM](https://dl.google.com/dl/android/maven2/androidx/appcompat/appcompat/1.3.1/appcompat-1.3.1.pom) declare Apache-2.0. The latter declares annotation 1.1.0, core 1.5.0, cursoradapter 1.0.0, activity 1.2.4, fragment 1.3.6, appcompat-resources 1.3.1, drawerlayout 1.0.0, savedstate 1.1.0, collection 1.0.0 and lifecycle-runtime/viewmodel 2.3.1. These are observed edges, **not** a complete graph or a lockfile for either candidate. Deeper AndroidX, Kotlin, Material and other actual selected artifact notices remain to be resolved and inspected.

The existing UVCAndroid AAR's 20 `.so` entries were read as bytes using ZIP and ELF header parsing, without extraction/execution or native loading. For all 20 libraries, all observed PT_LOAD segments had `p_align = 16384` (three load segments per library). The [UVCCamera makefile](https://github.com/shiyinghan/UVCAndroid/blob/fcdae5f9a194e2111d57019176b53470a120415b/libuvccamera/src/main/jni/UVCCamera/Android.mk) and [libyuv makefile](https://github.com/shiyinghan/UVCAndroid/blob/fcdae5f9a194e2111d57019176b53470a120415b/libuvccamera/src/main/jni/libyuv/Android.mk) also declare 16-KiB linker flags. This narrows the alignment unknown; it does not establish full 16-KiB compatibility.

Not validated: complete ELF structural correctness, PT_LOAD offset/address congruence, DT_NEEDED closure, final APK ZIP alignment/compression, loader behavior, hard-coded page-size assumptions, runtime allocations, 16-KiB device behavior or USB operation. Repeat those checks on the actual source-built output rather than transferring the inspected publication's result to a different build.

## Next-stage decision and exit conditions

Use the fixed UVCAndroid source as the **investigation baseline**, because it provides a narrower video path than AndroidUSBCamera's additional UAC/LAME/Kotlin helper surface. This is a choice of next work, not permission to skip missing provenance. Do not claim the locally rebuilt artifact is the upstream Maven publication; record the source commit, local patch set, toolchain and output hashes separately.

Before native code is linked into the Sidecar APK, complete all of the following:

1. **Source and build identity.** Preserve immutable upstream inputs and local changes. Pin JDK, Gradle, AGP, NDK, SDK/build tools and download checksums. Build only the selected library in an isolated workspace, with publishing/signing/upload tasks disabled. The inspected wrapper says Gradle 8.7, but the complete reproducible toolchain has not been established. Produce the resolved dependency graph, lock/verification data, build log and AAR plus per-library SHA-256 manifest.
2. **Native provenance and license material.** Resolve libyuv's precise upstream revision and missing root materials; audit the actual native compilation inputs and dynamic/static links. Prepare all applicable notices, corresponding source/modifications and replacement/relinking material for the selected distribution method. No unidentified prebuilt fallback is acceptable. If provenance remains unresolved, keep the native adapter blocked and continue with the simulated adapter.
3. **Publication divergence.** Verify the source-built graph and bytecode against the chosen fixed source. Ensure hutool is absent only when the actual built code does not require it; otherwise resolve and review its real use and license explicitly. Do not repair the inspected publication by suppressing an unresolved dependency edge.
4. **Minimal application integration.** Review merged permissions/features and actual API reachability. Exclude unused sample/audio/external-storage/media-store output and content logging paths. Bind explicit user consent, attempt identity, shared control barriers and buffer ownership to the app-owned adapter; upstream automatic open/preview behavior cannot bypass them.
5. **Artifact verification.** Inspect all final ABIs, DT_NEEDED dependencies, ELF segments and APK packaging/alignment. Verify source/build repeatability and review known advisories for the actual component versions. Only then run isolated loading and synthetic adapter tests. A successful native build/load is still not hardware acceptance.
6. **Separate hardware acceptance.** Keep real capture disabled until an authorized phone/card/hub/power/display combination passes the existing PRD gates. Actual format negotiation, readability, UVC/UAC separation, stop latency, hotplug, lock-screen visibility, timestamps, charging and long-run thermal/power behavior require device evidence. No README, license or static analysis substitutes for it.

No Gradle dependency resolution, upstream build, reproducibility comparison, complete notice audit or vulnerability scan has been performed in this review. No candidate is distribution-cleared, and no phone/capture-card combination is declared supported.
